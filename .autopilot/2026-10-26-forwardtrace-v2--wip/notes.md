### 1a. llm.py exactly
- NO openai SDK. Plain `httpx.AsyncClient` (module-level lazy `_client` via `_http()`, timeout `llm_timeout_sec`=180) POSTs to `f"{settings.openai_base_url}/chat/completions"` (Chat Completions, deliberately not the Responses API: comment cites a defect with structured outputs on the Luna tier), header `Authorization: Bearer <openai_api_key>`.
- Payload: `{"model": settings.openai_model, "messages": [{"role":"system","content":system},{"role":"user","content":user}], "response_format": {"type":"json_schema","json_schema":{"name":"result","strict":True,"schema":schema}}}`; if `settings.openai_reasoning_effort` is truthy then `payload["reasoning_effort"] = ...` else `payload["temperature"] = 0`. No max_tokens, no streaming, no tools.
- `@dataclass(slots=True) LLMResult(data: dict, model: str, elapsed_ms: int)`; `class LLMError(retry.ProviderError)`.
- `async complete_json(system: str, user: str, schema: dict) -> LLMResult`: runs `attempt()` inside `async with _llm_gate` (Semaphore(llm_concurrency=4)) and `retry.run(attempt, retries=settings.llm_max_retries, label="llm")`. `_parse_json(raw)` strips ``` fences, falls back to the first `{` .. last `}`; failure -> `LLMError(retryable=True)`. 429 containing "insufficient_quota" is non-retryable. Missing key -> `LLMError("OPENAI_API_KEY is not set")`.
- Cost is NOT returned: `costs.record_llm(body.get("model") or settings.openai_model, body.get("usage"))` is called inside `_call_openai` right after the HTTP JSON decode (before content parsing, so failed parses still count) and charges the ambient `costs.track()` meter through a ContextVar. Callers wanting numbers wrap the call in `with costs.track() as usage:`. LLMResult has no usage field.
- Sentry span op `gen_ai.chat`. `async aclose()` closes the client at shutdown. Defaults: model `gpt-5.6-luna`, effort `low`, prices 0 (cost recorded as $0 plus a startup warning).
- For v2 SSE chat a new streaming function is needed (`stream: true`, `stream_options: {"include_usage": true}`), then call `costs.record_llm` with the final usage.

### 1b. stt.py exactly
- `@dataclass(slots=True) STTResult(text: str, seconds: float | None, language: str | None, elapsed_ms: int, provider: str)`; `STTError(retry.ProviderError)`.
- `async transcribe(path: str, mime: str | None = None, locale: str | None = None) -> STTResult`. Language: `forced = (stt_language or "").split("-")[0].lower() or None`; `language = forced or (None if stt_detect_language(default True) else locale[:2])`. Sentry span op `ai.stt`; calls `costs.record_stt(result.provider, result.seconds)`.
- `_transcribe_deepgram(path, mime, language)`: reads the whole file (`asyncio.to_thread`), `POST {deepgram_base_url}/v1/listen` (httpx, shared client, timeout `stt_timeout_sec`=120), headers `Authorization: Token <key>`, `Content-Type: mime or application/octet-stream`, body = raw bytes. Query params: `model=nova-3`, `smart_format=true`, `punctuate=true`, `filler_words=false`, plus `language=<code>` OR `detect_language=true`. Wrapped by `retry.run(attempt, retries=stt_max_retries=2, label="stt")`.
- **STT_MULTILINGUAL**: when true `language = "multi"` overrides any pinned language, and keyterms are then NOT sent. Keyterms (`keyterm` repeated query param from `STT_KEYTERMS`) are sent only when a concrete language is pinned (not "multi", not detect) and the model starts with "nova-3".
- Response parsing: `payload["results"]["channels"][0]["alternatives"][0]["transcript"]`, `channel["detected_language"]` (falls back to settings.stt_language), `payload["metadata"]["duration"]`. **Word timestamps are discarded**: `alternatives[0]["words"]` (word, start, end, confidence, punctuated_word) is returned by Deepgram but never read. v2 must extend STTResult (e.g. `words: list[...]`).
- Local provider: faster-whisper (`_transcribe_local`, gate `Semaphore(stt_concurrency=1)`); dependency commented out in requirements.txt. Unknown provider -> STTError.

### auth.py (prefix /api/auth)
