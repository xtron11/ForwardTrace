## Что должно заработать

Шаг 1 «Порядка выполнения» второго брифа.

- **Повторная отправка.** Сообщение, отправленное три раза подряд (двойной клик, повтор после обрыва сети), сохраняется один раз и получает один ответ ИИ. Повтор не тратит лимит и не получает 409. Кнопки блокируются сразу после нажатия.
- **Цитата в строке.** Цитаты стоят внутри фразы, а не отдельными блоками.
- **Тон.** Всё, что говорит ИИ в диалоге, на «ты» и без форм с родом: первый разговор, протокол безопасности, шаблоны сообщений ИИ первым, требование тона в промпте разговора и в промпте тем. Интерфейс, письма и служебные сообщения бота остаются на «вы».
- **Час.** «уровень B1» больше не принимается за час.

Сам текст промпта разговора здесь не переписывается: это таск 14. Сейчас у прежнего промпта меняется только требование обращения, потому что точка отсчёта эталонов снимается уже на «ты».

## Критерии приёмки

- [ ] Три `POST /api/conversations/today/messages` с одним `client_msg_id` (подряд, после готового ответа) → одно сообщение человека, один ответ ИИ, один вызов `stream_chat`. Повторы получают поток с сохранёнными `user_message` и ответом (`delta`/`quote`/`done` с тем же `message_id`). Лимит считается один раз.
- [ ] Повтор, пока первый ответ ещё пишется → поток `user_message` + `done {message_id: null, duplicate: true}`, без 409 и без вызова модели. Событие `message_duplicate`.
- [ ] Голосовой повтор с тем же `client_msg_id` не пишет второй аудиофайл.
- [ ] Без `client_msg_id` два запроса = два сообщения, как раньше. Тесты Telegram зелёные без изменений.
- [ ] Кривой `client_msg_id` → 422 `bad_client_msg_id` (ru/en сообщение).
- [ ] Миграция `0017_client_msg_id`: колонка `messages.client_msg_id String(64) NULL` и уникальный `uq_messages_user_client_msg (user_id, client_msg_id)`, с рабочим downgrade. Модель совпадает (`_check_schema`).
- [ ] Фронтенд шлёт `client_msg_id` с каждым новым сообщением (текст, голос, быстрый ответ). «Повторить» после обрыва сети отправляет тот же id. Отправка, микрофон и быстрые ответы блокируются синхронно в обработчике нажатия.
- [ ] `QuoteChip` — inline: «цитата» и мелкая дата в той же строке. Меню по нажатию сохраняет переход к дню, аудио, «Это неточно», пометку `recalled`. Сравнение из первого разговора — один абзац на 375 px.
- [ ] Ключи `first.*`, `outreach.*` (кроме `outreach.push_title`, `outreach.reply_button`) и `safety.*` в `texts.py` на «ты», без «вы/вас/вам/ваш» и без форм с родом. Тест это проверяет; прежняя проверка «нет форм с родом» распространяется на все ru-строки. `first.greeting` и `first.comparison` — дословно по §2.4.
- [ ] `telegram.*`, `push.*`, `monthly.*`, письма и `lib/i18n.ts` остаются на «вы»; лендинг не тронут (G05). Нужно менять что-то вне второго и первого брифа — таск возвращается `BLOCKED` (R282).
- [ ] Промпты разговора, уровня 2 безопасности и тем outreach для ru требуют «ты» без форм с родом вместо `_address_formally`. Тесты, требовавшие ««вы»» в промпте и приветствии, переписаны.
- [ ] `parse_hour`: «уровень B1» → None (шаг переспрашивает), «в 9 вечера» → 21, «20:00» → 20, «8pm» → 20. Прямой тест.
