# 0012. Повторная отправка сообщения узнаётся по `client_msg_id`

## Контекст
Человек нажимал «отправить» несколько раз подряд, а после обрыва сети на середине ответа «Повторить» отправляло уже сохранённое сообщение второй раз. Сообщения и ответы ИИ дублировались, лимит тратился. Сообщения идут не только из приложения: Telegram и старые клиенты шлют без идентификатора.

## Решение
Клиент создаёт идентификатор на каждое новое сообщение (текст, голос, быстрый ответ) и хранит его вместе с неотправленным телом, поэтому «Повторить» шлёт тот же идентификатор. Сервер сохраняет его у сообщения и держит уникальным в пределах человека. Повтор узнаётся до проверок занятости, лимита и записи аудио: сначала по словарю в памяти процесса (ответ ещё пишется), затем по базе. На повтор отдаётся тот же поток событий без вызова модели: сохранённое сообщение и, если он уже есть, сохранённый ответ. Идентификатор необязателен; без него поведение прежнее.

## Почему
Рассмотрено: только блокировка кнопки на клиенте. Отвергнуто: она не спасает от повтора после обрыва сети, когда сообщение уже сохранено.
Рассмотрено: обязательный идентификатор. Отвергнуто: Telegram и старые клиенты его не шлют, их пришлось бы ломать.
Рассмотрено: на повтор снова вызывать модель и отдавать новый ответ. Отвергнуто: это тот самый дубль, который чиним, плюс лишняя стоимость и расход лимита.
Одной проверки в базе мало: пока первый ответ пишется, а сообщение ещё не закоммичено, повтор проскочит; поэтому нужен и словарь в памяти. Уникальный индекс остаётся страховкой от гонки.

## Последствия
- Миграция `0017_client_msg_id` добавляет колонку и индекс; строки без идентификатора (NULL) друг другу не мешают.
- Словарь в памяти работает, пока воркер один (ADR 0004); с несколькими процессами защитой останется только индекс, а ответ на повтор будет хуже.
- Если ответа на повтор ещё нет в базе, клиент получает `done` без `message_id` и перечитывает день: сам текст ответа повтор не гарантирует.
- Изменённый текст с тем же идентификатором будет принят за повтор и проигнорирован.
