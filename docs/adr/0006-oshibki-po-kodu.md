# 0006. Ошибки новых эндпоинтов — машинный код, перевод на клиенте

## Контекст
В v1 сервер отдавал английские строки, а фронтенд сопоставлял их регулярными выражениями. Одно из выражений («7-day») уже не совпадает с реальным текстом сервера («3-day»). Интерфейс двуязычный.

## Решение
Новые эндпоинты возвращают `{"detail": {"code", "message"}}`, фронтенд переводит ошибку по `code`; неизвестный код даёт общий текст «Что-то пошло не так». Каждый код из API обязан иметь строку в обоих словарях, и типы фронтенда не позволяют пропустить код. Старые эндпоинты аутентификации остаются со строками; для них показывается серверный текст только в известных случаях (409, 429, 410).

## Почему
Рассмотрено: переводить по тексту сообщения, как в v1. Отвергнуто: любая правка формулировки на сервере молча ломает перевод, а так уже случилось.
Рассмотрено: перевести и старые эндпоинты аутентификации. Не подошло: схема аутентификации не меняется без согласия владельца.

## Последствия
- В API два формата ошибок; клиент должен знать, какой где.
- Новый код ошибки — это изменение сразу на сервере и в двух словарях клиента.
- Серверное `message` остаётся для логов и отладки, пользователь его не видит.
