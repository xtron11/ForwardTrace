# 0003. Эмбеддинги фактов хранятся как JSON, сходство считается в Python

## Контекст
Нужен поиск фактов, близких по смыслу, и подбор пар «было → стало». Данных на бете мало, платных сервисов добавлять нельзя, база — Postgres на Railway, тесты идут на SQLite.

## Решение
Эмбеддинг лежит в поле факта как JSON, косинусное сходство считается в Python по фактам одного пользователя. Если эмбеддинг получить не удалось или модель эмбеддингов не задана, факт сохраняется без него, а поиск откатывается на последние факты по дате.

## Почему
Рассмотрено: pgvector. Отвергнуто для беты: расширение в базе и индексы ради десятков или сотен фактов на человека, а SQLite в тестах такой тип не поддерживает.
Рассмотрено: внешняя векторная база. Не подошло: платный сервис, который добавлять запрещено.
Откат на дату нужен, чтобы сбой или пустая настройка эмбеддингов не ломали ни ответ, ни извлечение памяти.

## Последствия
- Каждый поиск читает все факты человека в память; с ростом данных это станет узким местом.
- Переход на pgvector потребует миграции данных и переписывания поиска.
- Пока модель эмбеддингов не задана, пар по близости смысла нет, работают только пары по нитям; факты в контексте выбираются по дате.
