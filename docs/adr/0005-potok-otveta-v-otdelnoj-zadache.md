# 0005. Ответ ИИ идёт потоком SSE, но генерируется отдельной задачей

## Контекст
Ответ должен появляться сразу, по мере генерации. Вкладку человек закрывает посреди ответа, а сессия БД из зависимости закрывается до отправки тела ответа.

## Решение
Ответ отдаётся как Server-Sent Events через `StreamingResponse`. Генерацию ведёт отдельная `asyncio`-задача со своей сессией БД; она пишет события в очередь, а поток их читает. Если клиент отключился, задача доводит ответ до конца и сохраняет его. Проверки до начала потока (лимит, почта, размер и формат аудио, «ответ уже генерируется») выполняются раньше и возвращают обычный JSON с кодом ошибки.

## Почему
Рассмотрено: генерация прямо внутри генератора потока. Не подошло: отключение клиента отменяет генератор, ответ теряется, а человек после перезагрузки видит свой вопрос без ответа.
Рассмотрено: схема v1 — запрос, затем опрос статуса. Не подошла: ответ появляется только целиком, без ощущения живого собеседника.
Рассмотрено: использовать сессию из зависимости. Отвергнуто: она закрыта к моменту, когда поток начинает читать базу.

## Последствия
- Ошибки до потока и после него приходят разными путями: JSON с кодом и событие `error`. Клиент обязан разбирать оба.
- Нельзя отправить второе сообщение, пока идёт ответ; занятость хранится в памяти процесса и привязывает нас к одному воркеру (см. 0004).
- Частично сгенерированный текст при сбое модели не сохраняется, сообщение человека остаётся.
- Тесты разбирают SSE отдельным помощником.
