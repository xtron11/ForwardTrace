# 0004. Фоновые задачи живут в процессе API, один воркер

## Контекст
Нужны: извлечение памяти, закрытие дня, сообщения ИИ первым, месячные сводки, удаление аккаунтов. В v1 уже были `BackgroundTasks` и циклы в старте приложения; новые платные сервисы запрещены.

## Решение
Фоновая работа остаётся в процессе API: циклы на `asyncio` в старте приложения и `BackgroundTasks`, сервер запускается с одним воркером. Состояние хранится в базе, а не в памяти, поэтому циклы идемпотентны и после перезапуска доделывают работу по меткам в базе и уникальным ключам. Занятость разговора ответом — множество в памяти процесса.

## Почему
Рассмотрено: отдельный воркер с очередью. Не подошло: ещё один сервис и брокер на бете с одним владельцем и без пользователей.
Рассмотрено: несколько воркеров API. Отвергнуто: ограничитель частоты, занятость ответом и циклы работают в памяти процесса, и при нескольких воркерах они начнут дублировать работу и пропускать проверки.

## Последствия
- Горизонтально API масштабировать нельзя, пока эти вещи не вынесены в базу.
- Перезапуск посреди работы обрывает её; всё должно быть написано так, чтобы повтор не дублировал результат.
- Каждый новый цикл обязан ловить и логировать исключения, но пробрасывать отмену.
