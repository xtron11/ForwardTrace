# ForwardTrace — бэкенд

FastAPI-сервис разговорного дневника прогресса: один разговор на день человека, ответ
потоком, память из проверенных цитат, нити и «было → стало», ИИ пишет первым. Полный
справочник (эндпоинты, модель данных, настройки) — `DOCUMENTATION.md` в корне.

---

## Как запустить

```powershell
docker compose up -d db
alembic upgrade head
python -m uvicorn app.main:app --reload
```

Настройки — `.env` по образцу `.env.example` (для разработки `APP_ENV=development` и свой
`JWT_SECRET`). Документация API: `http://127.0.0.1:8000/docs`. `/health` отвечает только
«жив ли API и база»; какие провайдеры подключены, видно администратору в `/admin` и
`GET /api/admin/overview`. Деплой — `RAILWAY.md` и `DEPLOY.md`.

Скрипты: `scripts/make_account.py` (аккаунт без письма), `scripts/diagnose_stt.py`
(проверка Deepgram на одной записи), `scripts/eval_dialogs.py` (прогон диалогов из
`tests/eval/dialogs.yaml` настоящей моделью — платно).

## Тесты

```powershell
python -m pytest -o addopts= -q
```

Ни ключей, ни сервера базы не нужно: провайдеры (модель, поток, эмбеддинги, речь,
Telegram) подменяются в автофикстуре `fresh_db` (`tests/conftest.py`), данные — в файле
SQLite, схема пересоздаётся перед каждым тестом. **Тесты не читают ваш `.env`**:
`APP_ENV_FILE=""`, `DATABASE_URL` жёстко указывает на тестовую SQLite, ключи провайдеров
удаляются из окружения. Модуль, который импортирует провайдер по имени
(`from .llm import complete_json`), получает свою подмену в `fresh_db`.

Тесты миграций на Postgres (маркер `postgres`) идут только с `TEST_POSTGRES_URL` —
адресом одноразовой базы Postgres 16 (схема в ней сбрасывается).

## Решения, которые стоит знать

**Модель не пишет цитаты.** Она получает факты с id и пишет `{{quote:<fact_id>}}`;
`ReplyRenderer` подставляет цитату из базы и выбрасывает id, которого модели не давали.
Факт сохраняется только если его цитата проходит `verify.quote_supported` против текста
его же сообщения. Это проверка постфактум, а не просьба к модели не выдумывать.

**Ответ не зависит от соединения.** Генерация — отдельная `asyncio`-задача со своей сессией
БД; HTTP-поток только читает её очередь. Все проверки, которые могут отказать (почта,
лимит, аудио, «ответ уже идёт»), делаются до начала потока и отдаются обычным JSON.

**Память в фоне и идемпотентно.** Факты извлекаются, когда разговор затих
(`MEMORY_IDLE_MINUTES`), и при закрытии дня (`CLOSE_DAY_HOUR`). Всё в одной транзакции,
отметка `memory_extracted_at` в базе: рестарт не теряет и не дублирует.

**Числа считает код.** Дни, разговоры, закрытые нити, пары в сводке — SQL и Python; модель
пишет только три коротких текстовых поля. Процентов «пройдено к финишу» нет.

**Безопасность раньше всего.** Каждое сообщение человека проверяется до любой другой ветки,
включая онбординг; уровень 3 — шаблон без модели. Контакты помощи — только из
`SAFETY_RESOURCES`, которые заполняет владелец; код их не выдумывает.

**Таймзоны.** День человека — `local_date` по `users.timezone`; один разговор на
`(user_id, local_date)`, неделя лимита — пн–вс в его поясе, час сообщений ИИ — местный.

**Один воркер.** Фоновые циклы, ограничитель перебора и занятость разговора живут в
процессе; вторая реплика продублировала бы сообщения ИИ.

## Изменения схемы

Схемой управляет Alembic (`alembic/versions/`, имена ревизий вида `0015_drop_v1`). После
правки модели:

```powershell
alembic revision --autogenerate -m "что изменилось"
# прочитать файл ПЕРЕД накаткой: автогенерация — черновик, а не готовая миграция
alembic upgrade head
```

При старте `_check_schema` сверяет модели с базой и отказывается подниматься одной
понятной строкой, если колонки или таблицы не хватает. `AUTO_CREATE_TABLES=true` — только
для тестов.

`0015_drop_v1` удалила таблицы v1 (`entries`, `activities`, `reports`, `criteria`,
`tasks`, `task_mentions`) и `users.tasks_declined_on`; её `downgrade` возвращает схему, но
не данные. Импорт v1 (`scripts/import_v1.py`) удалён вместе с ними — он есть в истории git.
